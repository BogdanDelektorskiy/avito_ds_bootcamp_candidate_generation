# Кандидатогенерация для категории услуг Avito

Тестовое задание для отбора на Data Science Bootcamp от Авито

## Задача

Для каждого поискового запроса необходимо выбрать из корпуса не более 50 объявлений, которые будут переданы модели ранжирования. Целевая метрика: **Recall@50**. Релевантное объявление невозможно вернуть на следующих этапах каскада, если оно не попало в кандидаты

## Данные и признаки

В решении используются все три файла из задания

- `train.parquet` содержит положительные пары запросов и выбранных объявлений, по ним строятся история точных запросов с учётом локации, поиск похожих запросов и поведенческие priors
- `benchmark_queries.parquet` содержит запросы, для которых формируется итоговый список кандидатов
- `benchmark_items.parquet` содержит корпус объявлений, только из него выбираются итоговые `item_id`

Основные признаки и причины их использования

- `search_query` служит главным текстовым сигналом
- `item_title_raw` используется для быстрого словесного и символьного поиска
- `item_infm_params_text` и начало `item_description_raw` помогают находить услуги, которые не указаны в заголовке
- `search_category` и `item_category_id` используются как мягкий бонус за совпадение категории
- `search_location_id` и `item_location_id` используются как мягкий географический сигнал, но не как жёсткий фильтр
- `item_microcat_id` помогает уточнить тип услуги по похожим запросам из train
- `item_rating` и `item_rating_reviews_count` дают небольшой бонус объявлениям с подтверждённой историей отзывов

Текст поисковых фильтров и флаг доставки были изучены на этапе EDA. Фильтры не вошли в TF-IDF, но добавлены в BM25, где дают небольшой прирост на локальной проверке

## Решение

Используется гибридная кандидатогенерация из нескольких комплементарных источников:

1. символьный TF-IDF по заголовкам, устойчивый к опечаткам и словоформам
2. словесный TF-IDF по заголовкам
3. словесный TF-IDF по заголовку, параметрам и началу описания
4. BM25 по заголовку, параметрам и началу описания
5. отдельный BM25 по заголовку и параметрам
6. объявления, выбранные по похожим запросам из `train`
7. история точного текста запроса, если он встречался в обучающей выборке
8. слабый prior популярности объявления

Источники объединяются с помощью **Reciprocal Rank Fusion**. При финальном отборе также используются мягкие бусты категории, совместимой локации, прогнозируемой микрокатегории, рейтинга и числа отзывов

География не используется как жёсткий фильтр: только 83,1% положительных пар из `train` имеют одинаковые `search_location_id` и `item_location_id`. Для каждого поискового региона по обучающим взаимодействиям дополнительно определяются совместимые локации объявлений

Решение работает полностью локально и не обращается к внешним API

## Локальная валидация

Размеченная proxy-выборка построена из строк `train`, чьи `item_id` присутствуют в `benchmark_items`. Таким образом, поиск выполняется по тому же корпусу, что и для финального прогноза

Чтобы избежать утечки, все строки с текстами validation-запросов удаляются из данных, используемых для поведенческих признаков. Тексты объявлений остаются в поисковом корпусе, как и в реальной retrieval-задаче

| Подход | Recall@50 |
|---|---:|
| Символьный TF-IDF по заголовку | 0.2579 |
| Словесный TF-IDF по полному тексту | 0.3300 |
| BM25 по полному тексту | 0.3842 |
| BM25 по заголовку и параметрам | 0.2803 |
| Финальный гибрид | **0.6703** |

Зафиксирован `random_state=42`. Локальная метрика служит для сравнения подходов и не является оценкой скрытого benchmark

## Анализ ошибок

Основные типы ошибок:

- редкие синонимы, отсутствующие и в объявлениях, и в похожих train-запросах
- узкие услуги, упомянутые только глубоко в длинном описании
- несовпадение уровней географии: город, район или область
- короткие неоднозначные запросы с несколькими интентами

Для улучшения покрытия добавлены символьный поиск, поведенческие соседи и мягкая география. Текст описания ограничен первыми 2500 символами как компромисс между полнотой, памятью и скоростью

## Воспроизведение

Требуется Python 3.11+

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

Поместите файлы в каталог `data/`:

```text
data/
├── train.parquet
├── benchmark_queries.parquet
└── benchmark_items.parquet
```

После этого откройте `solution.ipynb` в VS Code, выберите интерпретатор `.venv/bin/python` и выполните все ячейки сверху вниз. Альтернативно путь к данным можно передать переменной окружения

```bash
AVITO_DATA_DIR=/path/to/dataset jupyter nbconvert \
  --to notebook --execute --inplace solution.ipynb
```

Ноутбук создаст `answer.csv` в корне проекта и проверит:

- наличие ровно двух колонок `query_id` и `answer`
- полноту и уникальность `query_id`
- не более 50 уникальных `item_id` на запрос
- формат идентификаторов
- принадлежность всех объявлений benchmark-корпусу

На MacBook с Apple Silicon полный запуск занимает несколько минут. Основная часть времени и памяти приходится на словесный TF-IDF по полным текстам объявлений
